# Getting help with Recall

Start with the [feature guide](docs/features.md),
[build instructions](README.md#build) and
[latest release notes](https://github.com/AbdulrahmanAhmedGit/Recall/releases).

- **Questions and usage help:** [GitHub Discussions](https://github.com/AbdulrahmanAhmedGit/Recall/discussions).
- **Reproducible bugs:** [bug report form](https://github.com/AbdulrahmanAhmedGit/Recall/issues/new?template=bug_report.yml).
- **Concrete feature requests:** [feature request form](https://github.com/AbdulrahmanAhmedGit/Recall/issues/new?template=feature_request.yml).
- **Security vulnerabilities:** the private channel in [SECURITY.md](SECURITY.md).
- **Conduct concerns:** [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

Include the Recall version, Android version/device, exact steps and expected versus
actual behavior. For UI problems, include language, theme and font scale. For review
issues, distinguish opening, skipping and rating a card. Keep screenshots and any
JSON example synthetic/redacted. Never post your full backup, private materials or secrets.

For reminders, check permission/channel access, quiet times, study windows, pauses
and device battery restrictions. The Scheduler information debug mode can help
diagnose decisions, but a successful test notification does not prove background
delivery timing. See [reminder troubleshooting](docs/reminders-and-full-backups.md).

For imported cards, provide the exact validation error and the smallest shareable
JSON example. See [science notation](docs/science-notation.md) and
[pronunciation](docs/PRONUNCIATION.md) for supported authoring rules.

Support is community/maintainer best-effort, without a guaranteed response time.
Do not uninstall, clear app storage or reset your database to troubleshoot without
first exporting and checking a full backup.
